# تقرير فحص مشروع: موقع NeuralCheck

- **التاريخ:** 2026-06-04
- **الفرع المفحوص:** `fix/hydration-mockup-i18n`
- **النطاق:** كامل المستودع (app، components، lib، public، docs، إعدادات البناء والنشر)

## 1. ملخّص تنفيذي

المشروع هو **الموقع التسويقي والخدمي لتطبيق NeuralCheck** — تطبيق Android يفحص الهواتف الذكية قبل الشراء عبر اختبار إجهاد مدّته 8 دقائق وتحليل بالذكاء الاصطناعي، ويُصدر تقريراً موثوقاً برمز QR. الموقع مبني على **Next.js 14 (App Router)** كـ **تصدير ثابت (static export)** ومنشور على **Firebase Hosting**، ويدعم **ثلاث لغات** (العربية افتراضياً، التركية، الإنجليزية).

الحالة العامة: **المشروع ناضج ومنظّم جيداً وجاهز تقريباً لمرحلة ما قبل الإطلاق (pre-alpha)**. الفرع الحالي `fix/hydration-mockup-i18n` يمثّل تتويجاً لعملية تدقيق شاملة: فقد طبّق **كل إصلاحات تقرير التدقيق** (تصحيح الأرقام المضلِّلة، إضافة صفحة تقنية، تسمية مزوّدي الذكاء الاصطناعي، تعريب الواجهات)، إضافةً إلى **إصلاحين دقيقين لمشاكل الـ Hydration**.

| البند | القيمة |
|---|---|
| نوع المشروع | موقع تسويقي + بوابة تحقق + لوحة تحكم مستخدم + لوحة إدارة |
| الإطار | Next.js 14.2.13 (App Router, JavaScript لا TypeScript) |
| النشر | تصدير ثابت → Firebase Hosting (مشروع `neuralchek-9b6d7`) |
| التنسيق | Tailwind CSS 3.4 + ثيم داكن مخصّص |
| الخلفية | Firebase (Firestore + Auth + Cloud Functions) |
| اللغات | 3 (ar / tr / en) عبر `LanguageContext` داخلي |
| عدد المسارات | ~15 مساراً عاماً + 6 صفحات إدارة |
| الدومين | neuralcheck.net |

## 2. ماهيّة المنتج

NeuralCheck (حسب المحتوى في `lib/i18n.js` و `app/technology/page.js`):

- **بروتوكول إجهاد من 8 مراحل** (~480 ثانية): قياس مرجعي → تخزين → ذاكرة → معالج → رسوميات → إجهاد مشترك → دفعات → تبريد.
- **~1,600 عيّنة قياس** عبر **11 قناة تتبّع عالمية** (تردد المعالج، الطاقة، جهد/تيّار/حرارة البطارية، أداء التخزين، عرض نطاق الذاكرة، FPS الرسوميات...).
- **"كموفلاج الذكاء الاصطناعي"**: استبدال الأحمال الاصطناعية بأحمال حقيقية (TensorFlow Lite MobileNetV2 + OpenGL ES raymarching) لتجاوز منظّمات الحرارة من المصنّعين (HyperOS / MIUI / ColorOS / One UI).
- **خط معالجة V6**: إرسال البيانات الزمنية الخام مباشرةً إلى نموذج AI (**DeepSeek V4-Flash** أساسي + **Gemini 2.5 Flash** احتياطي، ~46K رمز/فحص).
- **6 مؤشرات بطارية سلوكية** بدلاً من نسبة SoH وهمية.
- **تقارير بثلاث لغات** + تقييم بدرجات (A/B/C/D) ورمز QR للتحقق.

نموذج العمل: تنزيل APK مجاني، فحص مجاني واحد لكل جهاز، ثم باقات مدفوعة (فحص فردي $0.50 / متجر أساسي $10 شهرياً / متجر احترافي $20 شهرياً).

## 3. البنية التقنية والمعمارية

### التكوين الأساسي
- `next.config.js`: `output: 'export'` + `trailingSlash: true` + صور غير محسّنة → موقع HTML ثابت بالكامل، بلا خادم Node في الإنتاج.
- `firebase.json`: يخدم مجلّد `out/`، مع **rewrites ذكية** للمسارات الديناميكية ورؤوس تخزين مؤقت طويلة الأمد للأصول.
- `jsconfig.json`: اسم مستعار `@/*` للجذر.
- التنسيق: `tailwind.config.js` يعرّف لوحة ألوان كاملة بادئتها `nc-` (خلفية `#0A0E1A`، أخضر/سماوي/نيون) وخطوط Outfit + Tajawal وحركات مخصّصة.

### حيلة المسارات الديناميكية مع التصدير الثابت
بما أن `output: export` لا يدعم المعاملات الديناميكية، يستخدم المشروع نمطاً ذكياً: `generateStaticParams` يُرجِع عنصراً نائباً واحداً `{ slug: '_' }`، ثم تُعيد قواعد إعادة الكتابة في Firebase توجيه `/shop/**` و `/print/**` إلى صفحة `_` التي تقرأ المعرّف الحقيقي من المسار وقت التشغيل. (نفس المنطق مُحاكى محلياً في `.claude/serve-out.cjs`.)

### هيكل المجلّدات
```
app/         ← 15 صفحة (App Router): home, technology, verify, scan,
             pricing, privacy, terms, login, dashboard, shop/[slug],
             print/[shortId], admin/*  (+ layouts + not-found)
components/  ← 18 مكوّناً (Navbar, Footer, PhoneMockup, Stats, Particles...)
             + components/verify/* (6 مكوّنات لعرض التقرير)
             + components/admin/* (6 مكوّنات للوحة الإدارة)
lib/         ← i18n.js, LanguageContext.js, AuthContext.js, admin.js, format.js
public/      ← logo.svg, manifest.webmanifest, download/NeuralCheck.apk (36MB)
docs/        ← تقرير التدقيق المؤرشف
```

## 5. نظام تعدّد اللغات (نقطة قوة هندسية)

التصميم في `lib/LanguageContext.js` مدروس بعناية لتفادي أخطاء الـ Hydration:
- العرض على الخادم (SSR) والعرض الأول على العميل يبدآن **بالعربية حصراً** (`DEFAULT='ar'`)، فيتطابقان بايتاً ببايت.
- اكتشاف اللغة الفعلية (من `?lang=` → `localStorage` → `navigator.language`) يحدث **بعد** التركيب داخل `useEffect`، لا أثناء العرض.
- معامل `?lang=` يخدم تحديداً توليد PDF عبر Puppeteer (Chrome headless بلا localStorage).
- كل النصوص الثلاثة في ملف واحد (`lib/i18n.js`، ~1217 سطراً) بتكافؤ شبه كامل بين اللغات.

التنسيق في `lib/format.js` يفرض **الأرقام اللاتينية (0-9)** دائماً حتى في `lang=ar`، مع الحفاظ على أسماء الأشهر المترجمة — حل لمشكلة شائعة في الواجهات العربية.

## 6. التكامل مع Firebase والمصادقة

- `firebase.js`: تهيئة Firestore + Auth + Functions (منطقة `us-central1`).
- `lib/AuthContext.js`: يشترك في حالة المصادقة مرّة واحدة في الجذر، ويستدعي Cloud Function `registerUser` عند أوّل دخول لإنشاء وثيقة المستخدم — مع حماية من الاستدعاءات المكرّرة عبر `ensuredRef`.
- التحقق (`app/verify/page.js`) يعتمد على دوال سحابية: `verifyReport` (عبر HTTPS) و `generateReportPdf`، مع **قارئات دفاعية** تدعم عدة مخططات قديمة (`aiResponse.*` ثم `ai.*` ثم الحقول العليا).
- الإدارة (`lib/admin.js`): قائمة بريد إلكتروني ثابتة (`ADMIN_EMAILS`) للتحقق من صلاحية المشرف.

> **ملاحظة معمارية مهمّة:** الخلفية الحقيقية (دوال Cloud Functions و **قواعد أمان Firestore**) **ليست ضمن هذا المستودع**. الموقع واجهة فقط؛ نموذج الثقة والأمان الفعلي يعتمد على تلك المكوّنات الخارجية.

## 9. ملاحظات ومخاطر (من فحص مستقل)

أغلبها بسيط؛ لا توجد ثغرات حرجة:

🟡 **تسريب تشخيصي في الكونسول:** `components/admin/AdminGuard.js` (الأسطر 24-28) يطبع بريد المستخدم وقائمة `ADMIN_EMAILS` كاملةً في كونسول المتصفح، و`app/dashboard/page.js:395` يطبع حقول القائمة. ليست ثغرة (القائمة أصلاً في الحزمة العميلة)، لكنها **ضوضاء تشخيصية يُفضَّل إزالتها قبل الإنتاج**.

🟡 **الاعتماد الأمني على مكوّنات خارجية:** حماية المسارات الإدارية تعتمد على قائمة بريد عميلة + (يُفترض) قواعد Firestore غير الموجودة في المستودع. يجب التأكّد أن **قواعد أمان Firestore وملف Cloud Functions** يفرضان الصلاحيات فعلياً على الخادم، لا الواجهة فقط.

🟢 **مفاتيح ترجمة ميتة:** بعد إزالة المحتوى، بقيت مفاتيح غير مستخدمة (`login.noAccount`, `login.signup`, `verify.example`). غير ضارّة لكنها قديمة.

🟢 **hreflang غير حقيقي:** `app/layout.js` يوجّه ar/tr/en جميعها إلى `/` نفسها (لا مسارات لكل لغة). قد لا تُفهرس محرّكات البحث نسخ TR/EN جيداً. الزاحف يرى دائماً HTML العربية (RTL).

🟢 **README بسطر واحد** فقط؛ لا توثيق إعداد/نشر، لا اختبارات، لا TypeScript، لا ملف ESLint مخصّص.

🟢 **مفارقة معرّف المشروع:** معرّف Firebase هو `neuralchek-9b6d7` (بحرف c واحد) مقابل الدومين `neuralcheck.net` — مصدر التباس متكرّر عند التنقيح (مذكور في التدقيق).

🟢 **بقايا بنية تحتية:** يوجد worktree نشط `.claude/worktrees/gallant-jemison-6e0f9f/` يحتوي مجموعة جزئية من الملفات (عمل قيد التقدّم).
